# modbus: recovery from a TCP gap (response head)

Two long-lived modbus connections, 20 marked requests each (10.128.0.0 and 10.128.0.1 ->
10.0.0.2:502). Every frame travels in two TCP segments. In the capture, the first half of response 6 on the 10.128.0.0 connection is missing, so the data after the
gap starts in the middle of a response.

The parser resumes at the next plausible MBAP header in the response direction: that connection
logs all 20 requests and 19 of the 20 responses. No gap error is counted. The request whose response was lost is closed when the next response arrives, and no
invalid_protocol_id or invalid_length event is raised.

The pcap was generated by input.py.
