# Description

A mid-session HELO/EHLO resets the SMTP state only when the server accepts
it. Here the client starts an envelope as alice, sends an EHLO without the
required hostname, and receives a 501 rejection. It then completes the
original envelope. The rejected EHLO must not end alice's transaction or
move the remaining commands into a new one.

Redmine ticket: https://redmine.openinfosecfoundation.org/issues/8715

# PCAP

The pcap is a live capture of a real Postfix server, generated by the
email sandbox scenario `rejected-ehlo-preserves-envelope` in
`smtp-oddseq.py`.

The important sequence is:

```
---> helo client.example.com
<--- 250 mail.example.com
---> mail from:<alice@example.com>
<--- 250 2.1.0 Ok

---> ehlo
<--- 501 Syntax: EHLO hostname

---> rcpt to:<bob@example.com>
<--- 250 2.1.5 Ok
---> data
<--- 354 End data with <CR><LF>.<CR><LF>
---> (message body)
---> .
<--- 250 2.0.0 Ok: queued as <id>
---> QUIT
<--- 221 2.0.0 Bye
```

Postfix keeps the original envelope after rejecting the EHLO and delivers
the message from alice. The test checks that Suricata mirrors this with one
transaction containing alice's sender, bob's recipient, and the complete
message.
