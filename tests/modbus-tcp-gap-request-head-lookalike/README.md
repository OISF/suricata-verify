# modbus: recovery from a TCP gap whose tail looks like an MBAP header

Two long-lived modbus connections, 20 marked requests each (10.128.0.0 and 10.128.0.1 ->
10.0.0.2:502). Every frame travels in two TCP segments, and every request reads 10 registers
at address 0. In the capture, the first half of request 6 on 10.128.0.0 (its MBAP header) is
missing. What is left, 01 03 00 00 00 0a, reads as an MBAP header with protocol id 0 and
length 10, which would take the next request's bytes.

The parser rejects that match, since the message it yields has an invalid length, and resumes
at the next request: 10.128.0.0 logs 19 of its 20 requests, 10.128.0.1 all 20, and no
invalid_protocol_id or invalid_length event is raised.

The pcap was generated by input.py.
