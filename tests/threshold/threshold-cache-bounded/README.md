# threshold-cache-bounded

## Purpose

Regression test for uncontrolled growth (CWE-400) of the per-detection-
thread threshold *decision cache* in `src/detect-engine-threshold.c`
(`CheckCache`/`SetupCache`/`ThresholdCacheExpire`).

The cache memoizes suppressed decisions of IPv4 `limit` and `both`
thresholds tracked by source or destination. Every distinct tracked
address allocates a `ThresholdCacheItem` plus a generic hash-table bucket,
and the cache had no entry limit, byte budget, or memcap. Expiration
housekeeping runs at most once per whole packet-time second and examines at
most two entries, so a sender generating more than two new cache keys per
second makes the cache grow without bound (memory DoS). The cache also uses
a fixed 256-bucket hash table that is never rehashed, so lookups degrade
linearly with the number of entries (CPU DoS).

## What the test checks

1. **Functional** (works pre- and post-fix): 100000 unique sources each
   send three matching UDP packets in the same second; the rule
   (`limit, count 1, seconds 1, by_src`) must alert exactly once per
   source — the 2nd packet is the silent match that creates the cache
   entry, the 3rd packet is a silent match served by the cache — plus the
   final packet from a fresh source. Total: 100001 alerts.
2. **Regression** (fails pre-fix): after 100000 distinct keys, the new
   global counter `detect.thresholds.cache.memuse` (bytes held by the
   decision cache, registered alongside the other `detect.thresholds.*`
   counters) must be ≤ 64 KiB. Pre-fix the counter does not exist (the
   stats check fails) and the unbounded cache holds ~10 MiB for this
   capture.

The test asserts the bound on default configuration; the cap itself
(`detect.thresholds.cache.max-entries`, default 256 per thread) is part
of the fix contract this test validates.

## PCap

Generated by `writepcap.py` in this directory (committed next to the
pcap): 100000 unique `10.x.y.z` sources × 3 UDP/9999 packets with payload
`CACHE9` at t=1000, plus one final packet at t=1003 from 203.0.113.250
which alerts and triggers a housekeeping pass. Classic pcap (not
pcapng); validated with tshark.

## Running

    cd <suricata-src>
    ../suricata-verify/run.py threshold-cache-bounded

## Notes

- `--runmode=single` is used so the per-thread cache is a single cache and
  the memory bound is deterministic.
- The original black-box proof of concept (400000 unique sources, 256 MiB
  address-space limit, process termination via SIGABRT) is too
  environment-dependent for CI; this test uses stats-based assertions that
  are deterministic across machines.
