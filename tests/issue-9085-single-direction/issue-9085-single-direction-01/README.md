# issue-9085-single-direction-01

Redmine ticket: https://redmine.openinfosecfoundation.org/issues/9085

A TFTP request transaction must not be inspected in the to-client
direction.

TFTP builds a transaction from a to-server request datagram only;
`TFTPParseResponse` is not implemented, so no transaction is ever created
to-client. Before the fix the transaction was created without the
per-direction SKIP_INSPECT bits, so it was also inspected to-client and a
matching rule alerted on a server packet of the same flow, reporting the
request transaction.

The pcap is synthetic and was generated by the `generate-pcap.py` script in
this directory. It was not captured from any network.
