# nfs4-createsession-partial-write

Three NFSv4 `CREATE_SESSION` + oversized `WRITE` compounds, one per
channel variant (`AUTH_NONE`, `AUTH_SYS`, non-empty `RDMA`), each in a
record that declares a size larger than the data ever arrives.

`CREATE_SESSION` is not in the partial-scan skip table: its
`channel_attributes4` / callback-security fields are variable-length
(a `RDMA` layout carries a non-empty channel netid), so advancing past
the op by a fixed layout is not wire-faithful and could land the scanner
mid-record. A mid-record `Incomplete` would buffer the whole record
toward the (attacker-controlled) 31-bit RPC marker (Redmine #8791).

Instead, the scanner applies bounded rejection: a non-last op whose
arguments cannot be reliably skipped makes the whole compound
`Malformed`. The record is rejected and skipped to its marker boundary,
so the 17 MiB `WRITE` claim can never drive buffering. (A
`CREATE_SESSION` that is the *last* op of the compound is concluded
clean, since nothing follows to hide a `WRITE`.)

Each record is fed over two 4 KiB packets with the server acked in
between so the first packet is scanned in isolation. The check asserts
the three `malformed_data` events (safe rejection), and — by
construction — the parser never buffers toward the claim.

Generated by `gen_nfs_review_tests.py` (test F).
