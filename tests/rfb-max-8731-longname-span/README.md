# Test Description

Regression test for the out-of-bounds slice introduced by PR 16159
(v3.4) while fixing the truncated-string over-skip of ticket #8731: a
ServerInit name longer than `app-layer.protocols.rfb.max-string-length`
that spans multiple TCP segments must be truncated without crashing the
engine.

In the `TCServerInit` branch the v3.4 code does:

    current = &rem[request.to_skip as usize..];

where `rem` is the input left over after the capped `take(cap)` of the
name. When the name straddles the input-buffer boundary (the buffer
holds at least `cap` but fewer than `name_len` name bytes — the normal
multi-segment case), `rem.len() < to_skip = name_len - cap` and the
slice is out of bounds: Rust panic in a non-unwindable FFI function,
engine abort (remote DoS via any RFB server with a > 4 KiB name). The
correct pending skip is `to_skip` minus the tail bytes already present
in the buffer.

## PCAP

Generated by make_pcap.py. RFB 3.8 handshake, security type 2 (VNC
auth — spec-compliant path, so the test is independent of the separate
None-path security-result issue): version exchange, 1 security type
(VNC auth) offered and selected, 16-byte challenge / 16-byte response,
4-byte big-endian security result 0 (OK — the width modeled by both the
parser's `be_u32` and tshark's VNC dissector), shared flag 1, then the
ServerInit: 1024x768, 32bpp true colour, a 10000-byte name ('N') sent
in 1400-byte TCP segments so it spans buffer boundaries, then a clean
TCP close (EOF) so the transaction is logged.

## tshark validation

The handshake is fully dissected as VNC: both protocol versions,
`num_security_types: 1`, `security_type: 2`, `client_security_type: 2`,
`auth_challenge` / `auth_response`, `Authentication result: OK`, the
`Share desktop flag`, and the ServerInit (`Framebuffer width: 1024`,
`height: 768`, pixel format, `Desktop name length: 10000`). No payload
is left as undecoded data.

Known tshark dissector limitation: the VNC `SERVER_INIT` state reads
the desktop name from the current packet's tvb without requesting
desegmentation (unlike the dissector's other states), so a name that
spans TCP segments makes tshark emit a "Malformed Packet (Exception
occurred)" expert item when it reads the name — a real VNC stream with
a spanning name hits the same limitation. The name-spanning shape is
intentional here: it is exactly the case the regression test pins.

## Checks

- exactly one `rfb` event with the full handshake
  (`security_type: 2`, `security_result: OK`, `screen_shared: true`)
  and the ServerInit fields with the name truncated to the 4096 cap
  (`framebuffer` 1024x768, `name.__len: 4096`) — only present when the
  flow was parsed end to end without aborting;
- exactly one `rfb.too_long_string` anomaly.

Against PR 16159 (v3.4) the engine aborts during the test
(`panicked at src/rfb/rfb.rs: range start index 5904 out of range for
slice of length 80`); against a fixed parser the test passes.
