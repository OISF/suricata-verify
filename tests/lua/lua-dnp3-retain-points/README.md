Reproducer for the lazy DNP3 points userdata lifetime (lua/dnp3:
materialize transaction points lazily). The points userdata of an
object with more than 32 points holds pointers into
transaction-owned memory; a script can retain it in module state, and
without a lifetime guard a later `retained[1]` follows the dangling
cursor after the transaction is freed (use-after-free / stale heap
read, fully observable under an ASan build).

test.pcap (regenerated by make-pcap.py) is two DNP3 connections on the
same 5-tuple. Phase 1 carries one request with a 33-point group-1
variation-1 object (above the 32-point eager threshold, so the lua
`points` value is the lazy userdata); the first detection callback
retains that value in a module global. The gap between the connections
exceeds the default established-flow timeout (300s), so the first
connection's flow — and its DNP3 state, which owns the retained
transaction — is freed before the second connection's callback runs on
a new DNP3 state (same worker, since the 5-tuple is unchanged). The
retained userdata's lifetime check then fails and `points[i]` reads
nil, while the second connection's own `points` value is still alive;
the rule alerts on exactly that.

The fixed code invalidates the retained userdata (any index access
after the transaction is gone returns nil) and alerts once. Pre-fix
code reads the stale transaction-owned memory instead (no alert) or
crashes under ASan.
