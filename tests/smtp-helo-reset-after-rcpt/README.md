# Description

A HELO/EHLO issued mid-session must reset the SMTP state exactly as if a
RSET had been issued (RFC 5321 4.1.4). Same as smtp-ehlo-reset, but this
fixture uses HELO and the abandoned envelope also has a recipient. The
HELO discards a MAIL FROM and a RCPT TO before the second message is sent.

Redmine ticket: https://redmine.openinfosecfoundation.org/issues/8715

# PCAP

The pcap is a live capture of a real Postfix server, generated by the
email sandbox scenario `helo-reset-after-rcpt` in `smtp-oddseq.py`.

The important sequence is:

```
---> ehlo client.example.com
<--- 250-mail.example.com (multiline)
---> mail from:<alice@example.com>
<--- 250 2.1.0 Ok
---> rcpt to:<bob@example.com>
<--- 250 2.1.5 Ok

---> helo client.example.com
<--- 250 mail.example.com

---> mail from:<bob@example.com>
<--- 250 2.1.0 Ok
---> rcpt to:<alice@example.com>
<--- 250 2.1.5 Ok
---> data
<--- 354 End data with <CR><LF>.<CR><LF>
---> (message body)
---> .
<--- 250 2.0.0 Ok: queued as <id>
---> QUIT
<--- 221 2.0.0 Bye
```

Postfix clears the full envelope at the HELO and delivers the message
from bob. The test checks that Suricata mirrors this: two transactions,
the first holding alice's abandoned envelope (sender and recipient, no
message), the second holding bob's complete message.
