# tls-version-fragmented-hello

A ClientHello whose first TLS record carries only the handshake header and
whose body (with the negotiated hello version) arrives in the next record.
The parser enters the `client_hello` phase on the first record, when the only
known version is the record layer version (0x0301 / TLS 1.0); the negotiated
version (0x0303 / TLS 1.2) is decoded only when the second record completes
the handshake message.

`tls.version` matches the negotiated version and is registered at the hello
states, so the early miss stays revisitable and the keyword matches the
completed hello. Before the fix it was registered at the started state
(progress 0), where the miss became final as soon as the phase advanced - a
fragmentation evasion.

The match is evaluated on the first to-server app layer update after the
hello completes (the fixture's frame 8), so the test pins the alert's
`pcap_cnt` to 8 rather than to the completing frame 6. Same scheduling as the
existing `tls-client-hello-frag-01` fixture, where the hello completes at
frame 6 and the alert lands at frame 11.

`ssl_version` matches the record layer version and stays on the shared
`tls_generic` buffer at the started state. On this fixture the records are
0x0301, so `ssl_version:tls1.0` matches (on frame 6, when the phase starts)
and `ssl_version:tls1.2` does not.

The pcap is generated by `craft-pcap.py`.
