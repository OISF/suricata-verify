# Redmine #8818 IPv6 defrag payload-length overflow

Regression test for https://redmine.openinfosecfoundation.org/issues/8818.

The pcap is generated by `make-pcap.py` with Scapy. It contains one IPv6 UDP
datagram split across 46 fragments. The first fragment has an 8-byte
Destination Options header before its Fragment header, while the fragmentable
portion ends at byte 65,528. Reassembly would therefore produce a 65,536-byte
IPv6 payload, one byte beyond the 16-bit IPv6 payload-length limit.

Vulnerable builds store that length in the 16-bit IPv6 payload-length field and
pass a narrowed packet length to the second decode, causing both lengths to
wrap. The rebuilt UDP datagram then bypasses protocol and content inspection.

A fixed build rejects the oversized reassembly, raises
`ipv6.frag_pkt_too_large` on the final fragment, and does not count the chain as
reassembled.

PCAP SHA256: `0fd8e52eb4771bca042914e480d93375412fec6f69ada7eadcbc7f064f3268a8`.
