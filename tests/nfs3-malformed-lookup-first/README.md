# nfs3-malformed-lookup-first

The LOOKUP argument parse lives in its own helper, which used to raise
`malformed_data` on "the last transaction" - none on the first record of a
flow, so the event vanished. This fixture makes the malformed LOOKUP the
first record, which is the case that was silently dropped.

Generated by `nfs3-malformed-lookup-first.py`: v3 LOOKUP with 3 argument
bytes (a dirpath3 needs a 32 byte handle plus a name), then an FSSTAT with a
proper filehandle3.
