# nfs4-sequence-read-partial

A fragmented NFSv4.1 `SEQUENCE; PUTFH; READ` reply where the read is within
the `max-read-size` limit.

A typical NFSv4.1 compound reply leads with a `SEQUENCE` op. The partial
response scanner (which walks the compound to find an oversized `READ`
before the RPC record is buffered) must skip the `SEQUENCE` op's successful
result — a 36-byte `nfs41_sequence_ok` (ssn4 + seqid + slots + flags) — to
reach the following `READ`. Without that skip the `SEQUENCE` op is "not
reliably skippable" and the compound is rejected as malformed, so the read
data is never inspected.

The reply is split over two packets with the peer acked in between so the
first packet is scanned in isolation. The read is within the limit, so the
scan is `Incomplete` (the data is not all buffered yet), the record
completes, and the 8192-byte read is inspected.

The check asserts the `fileinfo` event for the 8192-byte read and that no
`malformed_data` anomaly is raised.

Generated by `gen_nfs_review_tests.py` (test H).
