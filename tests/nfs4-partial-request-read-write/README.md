# nfs4-partial-request-read-write

A fragmented NFSv4 `PUTFH; READ; WRITE` request where the write is within
the `max-write-size` limit.

A valid request compound can carry a `READ` op before a `WRITE` op. The
partial request scanner (which walks the compound to find an oversized
`WRITE` before the RPC record is buffered) must skip the `READ` op's
arguments — stateid + offset + count, 28 bytes — to reach the following
`WRITE`. Without that skip the `READ` op is "not reliably skippable" and the
compound is rejected as malformed, so the write data is never inspected.

The request is split over two packets (the first ends at the `READ` op tag)
with the peer acked in between so the first packet is scanned in isolation.
The write is within the limit, so the scan is `Incomplete` (the write data
is not all buffered yet), the record completes, and the 8192-byte write is
inspected.

The check asserts the `fileinfo` event for the 8192-byte write and that no
`malformed_data` anomaly is raised.

Generated by `gen_nfs_review_tests.py` (test I).
