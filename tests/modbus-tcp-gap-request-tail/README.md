# modbus: recovery from a TCP gap (request tail)

Two long-lived modbus connections, 20 marked requests each (10.128.0.0 and 10.128.0.1 ->
10.0.0.2:502). Every frame travels in two TCP segments. In the capture, the second half of request 6 on 10.128.0.0 is missing (a TCP gap inside a frame).

After the gap the next request starts at an MBAP header. The parser carries on: 10.128.0.0 logs
19 of its 20 requests (the response to the lost one is logged on its own), 10.128.0.1 all 20. No gap error is counted. No invalid_protocol_id or invalid_length event is raised.

The pcap was generated by input.py.
