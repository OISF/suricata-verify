# nfs3-short-read-continuation

A short v3 `READ` reply (`data_len` 100 < `count` 1000) inside a complete
record must not arm a count-based chunk promise. The promise outlives the
record and the following reply's bytes (request + response) get consumed
as the short read's chunk continuation, losing the next read's file data
and desyncing the stream.

The tracker and the chunk state follow the data actually present in the
reply (`data_len`, not the requested `count`), so the following read's
new data is stored and the file closes complete.

Checks (file logging on):

- the file is exactly the 1024 bytes of wire data (the 512 bytes of the
  first read + the 512 bytes of the third; the short read's 100 bytes are
  a covered retransmission of the tracked region and are discarded), with
  the sha256 of that data, state `CLOSED`, no gaps;
- the third read's response is logged as an `nfs` event (proving its
  reply was parsed as a record, not eaten as chunk data);
- no `malformed_data` events.

Generated by `gen_nfs_review_tests.py` (test M).
