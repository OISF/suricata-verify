# Redmine issue 8980

Regression test for DNP3 transaction inspection after link-layer framing
errors.

The capture contains three flows:

1. A request with an invalid link-header CRC followed by a valid request in the
   same TCP segment.
2. A valid request followed by a response with an invalid link-header CRC and
   a valid response in the same TCP segment.
3. A valid request followed by a to-client user-data frame that is too short
   for the response headers and then a valid response in the same TCP segment.

Before the fix, each bad CRC returned a fatal parser error and prevented
inspection of the later valid frame. The parser must resynchronize in both
directions without using the length from a CRC-invalid header. The short
response has a trusted frame length, so the parser must consume that frame and
continue with the valid response instead of returning a terminal error.

`input.pcap` is generated by `create-pcap.py`.
