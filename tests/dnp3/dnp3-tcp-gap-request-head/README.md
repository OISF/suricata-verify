# dnp3: recovery from a TCP gap (request head)

Two long-lived dnp3 connections, 20 marked requests each (10.128.0.0 and 10.128.0.1 ->
10.0.0.2:20000). Every frame travels in two TCP segments. In the capture, the first half of request 6 on 10.128.0.0 is missing, so the data after the gap starts in the
middle of a frame.

The parser resynchronizes on the next link-layer start bytes: 10.128.0.0 logs 19 of its 20 requests,
10.128.0.1 all 20. No gap error is counted.

The pcap was generated by input.py.
