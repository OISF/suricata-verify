# dnp3: recovery from a TCP gap (request tail)

Two long-lived dnp3 connections, 20 marked requests each (10.128.0.0 and 10.128.0.1 ->
10.0.0.2:20000). Every frame travels in two TCP segments. In the capture, the second half of request 6 on 10.128.0.0 is missing (a TCP gap inside a frame).

After the gap the next request starts with the link-layer start bytes. The parser drops the partial
frame and carries on: 10.128.0.0 logs 19 of its 20 requests, 10.128.0.1 all 20. No gap error is counted.

The pcap was generated by input.py.
