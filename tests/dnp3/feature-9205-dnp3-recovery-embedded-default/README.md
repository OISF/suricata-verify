# Redmine feature 9205 — frame embedded in a failed frame

Two flows. In the first, a valid exchange, then, in one segment, a frame whose
link header is valid but whose 16-octet data block fails its CRC and contains a
complete valid request, followed by a valid request. In the second, the other
direction: a valid exchange and a request, then, in one segment, a response
whose data block fails its CRC and contains a start sequence followed by an
invalid link header, followed by a valid response. `input.pcap` is generated by
`create-pcap.py`.

With `resync-on-bad-start` off (this test) the parser skips the failed frame by
its `LENGTH` (`dnp3.bad_transport_crc`): the embedded request is not parsed, and
the request after the failed frame is logged and marked with
`dnp3.after_resync`. In the second flow the failed response is skipped the
same way and the valid response behind it is logged and marked.
`feature-9205-dnp3-recovery-embedded-resync` runs the
same capture with the option on.
