# Redmine feature 9205 — frame embedded in a failed frame

One flow: a valid exchange, then, in one segment, a frame whose link header is
valid but whose 16-octet data block fails its CRC and contains a complete valid
request, followed by a valid request. `input.pcap` is generated by
`create-pcap.py`.

With `resync-on-bad-start` off (this test) the parser skips the failed frame by
its `LENGTH` (`dnp3.bad_transport_crc`): the embedded request is not parsed, and
the request after the failed frame is logged and marked with
`dnp3.policy_divergence`. `feature-9205-dnp3-recovery-embedded-resync` runs the
same capture with the option on.
