# dnp3: recovery from a TCP gap (response head)

Two long-lived dnp3 connections, 20 marked requests each (10.128.0.0 and 10.128.0.1 ->
10.0.0.2:20000). Every frame travels in two TCP segments. In the capture, the first half of response 6 on the 10.128.0.0 connection is missing, so the data after the
gap starts in the middle of a frame.

The parser resynchronizes on the next link-layer start bytes in the response direction: that
connection logs 19 of its 20 responses and all 20 requests. No gap error is counted.

The pcap was generated by input.py.
