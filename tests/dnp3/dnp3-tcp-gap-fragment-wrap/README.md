# dnp3: TCP gap inside a multi-frame fragment

One dnp3 connection. A WRITE of 120 group 30 variation 1 points (every octet 0x41) travels as a
three-frame application fragment with transport sequence numbers s, s+1, s+2, one frame per
TCP segment; the middle segment is missing from the capture. After 61 single-frame Reads, a
second WRITE (every octet 0x42) uses s, s+1 and s+2 again, since the transport sequence number
wraps every 64 segments.

On a gap the parser closes the open transactions in that direction. The first WRITE is logged
incomplete, and the second WRITE is reassembled from its own frames: complete, with its first
point's value 0x42424242. If the first WRITE stayed open, it would take the second WRITE's
continuation frames, and the second WRITE would never be logged.

The pcap was generated by input.py.
