# Redmine issue 8979

Regression test for a DNP3 link-layer decoder event raised before the first
transaction.

Each flow starts with a DNP3 frame with an invalid link-header CRC before a
current transaction exists. One sends the bad frame to-client; the other sends
it to-server. Before the fix, the parser discarded these events. The parser
must create an event-only transaction so the bad-link-CRC rule alerts once in
the direction carrying the bad frame.

Valid application data follows in the opposite direction. The event-only
transaction must be skipped in this direction so the directionless event does
not alert a second time. The event-only carrier must also remain suppressed
from DNP3 transaction logging.

`input.pcap` is generated by `create-pcap.py`.
