# Redmine feature 9205 — long session and split first segment

The capture contains two flows:

1. A long session: a valid exchange, a request with an invalid link-header CRC
   followed by a valid request in the same TCP segment, then three more
   exchanges. `dnp3.policy_divergence` is raised once, on the first request
   behind the error, not on the rest of the session.
2. Twelve octets without a `0x05 0x64` start sequence in the first segment of
   the flow, and a valid request in the next segment; the server does not
   answer, so only the to-server side can detect the protocol. With
   `resync-on-bad-start` off (this test) the to-server side is not detected
   as DNP3 and the request is not logged.

`feature-9205-dnp3-recovery-session-resync` runs the same capture with the
option on. `input.pcap` is generated by `create-pcap.py`.
