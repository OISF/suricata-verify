# ruletype-firewall-242-lte-http1-request-header-keywords

Per-buffer validation of the remaining request-header (HEADERS) `app_stream`
registrations: `http.header`, `http.cookie`, `http.host.raw`,
`http.user_agent`, `http.header_names` and `http.start` (tosever).
Complements test 234, which covers `http.host` at the same progress value.

## Scenario

Six LTE rules, one per buffer, all with hook `http1:<request_headers`:

* sid:211 `http.header; content:"X-HdrA: a1"`
* sid:212 `http.cookie; content:"sca=cookieA"`
* sid:213 `http.host.raw; content:"hostA.example.com"`
* sid:214 `http.user_agent; content:"AgentA/1.0"`
* sid:215 `http.header_names; content:"X-HdrB"`
* sid:216 `http.start; content:"X-StartA: s1"`

Pcap (generated by `generate-pcap.py`) carries 12 flows. The request line
plus the Host/Accept headers complete in the first segment (progress moves to
request_headers); the discriminating headers arrive in the second segment.

* A1-A6 (ports 49190-49195): segment 2 carries all six marker headers; the
  flows are accepted (the host.raw keyword can already match on the first
  segment, the other five match when the second segment is parsed).
* B1-B6 (ports 49196-49201): segment 2 carries X-HdrZ/Cookie
  sca=cookieB/User-Agent AgentB/2.0/X-Other/X-StartB and host
  hostB.example.com - none of the six keywords matches; each flow is dropped
  once.

The header buffers populate line by line during the HEADERS progress, so the
no-match of the first segment (before the second segment's headers are
parsed) is PROVISIONAL at the rule's own hook state and must not be converted
to CANT_MATCH (all six buffers are streaming). Each B flow is rejected by the
engines' own eof CANT_MATCH; streaming defers the decision, it never waives
the drop.

## Expected

exactly 6 `firewall default app policy` drops (one per B flow).
