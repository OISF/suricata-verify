# ruletype-firewall-235-lte-http1-request-body-segmented

Regression test: the request body split over two TCP segments; the body can still grow at the request_body progress - validates the keyword behaviour at this HTTP
progress value on both sides: a provisional (late) no match must not be turned
into a definitive no match (CANT_MATCH) while the buffer can still receive
data, while a definitive no match must still drop the flow.

## Scenario

`accept:flow http1:<request_body $HOME_NET any -> $EXTERNAL_NET any (http.request_body; content:"second"; sid:211;)`.

Pcap (generated by `generate-pcap.py`, see `input.pcap`) carries two flows:

* A (port 49157): second body segment contains the keyword; B (port 49158): second body segment does not

## Expected

exactly 1 `firewall default app policy` drop (flow B): flow A is accepted when the second body segment matches, flow B is dropped when the completed body is definitively no-match (eof CANT_MATCH).
