LTE http2 rule matched by a trailer HEADERS frame
=================================================

`http2:stream:<request_headers` with `http.header; content:"x-note"`: the header only
appears in the trailer HEADERS frame at packet 8, which moves the same tx to
`request_closed` (3), two states above the hook (`request_headers`, 1). Coverage for the hook has to stay
open until the sub-state completes, so the later frame must be able to decide the flow.

input.pcap is generated by gen_input_pcap.py: literal HPACK, no external modules.

Which leg this pins: the engine-finality one. `DetectTxCompleted()` must not call the tx data final
while the sub-state can still grow the buffer, so the rule stays revisitable - that is the
`DetectLteRevisit()` leg, added on the firewall-bug2727/hook-mask line. Measured on `70fb62bb3`
alone this test passes without the MPM candidacy work, so do not read it as coverage of that: the
candidacy path is asserted by unit tests (`DetectFwLteCoverageTest01`-`03`,
`DetectFwLteMpmWalkTest01`), the window bookkeeping by `PrefilterLteWindowTest01`-`05`.

Re-running the generator is equivalent but not byte-identical: scapy stamps each
packet with the current time, so only the pcap timestamps differ.
