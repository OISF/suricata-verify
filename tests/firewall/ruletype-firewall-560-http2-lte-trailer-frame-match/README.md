LTE http2 rule matched by a trailer HEADERS frame
=================================================

`http2:stream:<request_headers` with `http.header; content:"x-note"`: the header only
appears in the trailer HEADERS frame at packet 8, which leaves the same tx at
`request_closed` (3), two states above the hook (`request_headers`, 1). The rule is not
kept open for that update; it reaches it because above the retirement bound the group
goes into the candidate list whole, so the trailer still gets inspected.

The app default here is `accept:hook`. That matters: with a `drop:flow` default the
request_headers policy decides on packet 6, the first DATA frame, and the trailer at packet 8 is
never reached; main behaves the same way. To see that variant, make the http2 default
`drop:flow` and give the response direction an `accept` so the flow still ends accepted: the
policy then decides on packet 6 and 110 never fires at packet 8.

input.pcap is generated by gen_input_pcap.py: literal HPACK, no external modules.

Re-running the generator is equivalent but not byte-identical: scapy stamps each
packet with the current time, so only the pcap timestamps differ.
