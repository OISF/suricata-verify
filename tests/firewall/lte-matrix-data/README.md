# LTE state matrix data

Shared pcaps and generators for the generated LTE (`<hook`) state matrix tests
(`ruletype-firewall-3xx/4xx/5xx-lte-<proto>-*`).

- `generate-pcap.py` — builds `http1.pcap`, one HTTP/1 request/response that
  visits every hookable progress state in both directions with distinct
  markers per state. Segments are split per phase so each state is observed.
- `generate-smtp-pcap.py` — builds `smtp.pcap`, one SMTP session whose mail is
  a multipart/mixed message with three attachments (a base64 PNG, a
  quoted-printable text part and a 7bit raw part), so the MIME parser streams
  a realistic multi-attachment body through the `email.*` buffers registered
  at request_data. The DATA payload is split so the headers and the parts are
  parsed in separate passes.
- `http1.pcap` / `smtp.pcap` — the generated fixtures.
- the tls cells reuse
  `tests/tls/tls-client-hello-frag-01/dump_mtu300.pcap`.
- the http2 cells reuse `tests/http2-bugfixes/input.pcap` (cleartext HTTP/2),
  covering the stream and global transaction types.

The test directories are generated by `../generate-lte-state-matrix.py`; do not
hand edit them, rerun the generator instead. The checks pin the packet each
alert and each default-policy drop lands on (`pcap_cnt`); the per-state timeline
lives in the generator's `WHEN` table.

Not generated: the tls toclient cells that need the toclient track to reach its
completion state (`server_finished`, and the `server_data` no-match case). At
flow close only the direction of the final ACK gets the EOF evaluation, so such
rules are never adjudicated; re-enable them when the final evaluation is done
for both directions.
