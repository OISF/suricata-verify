# ruletype-firewall-236-lte-http1-response-line-split

Regression test: the response status line split over two TCP segments; the stat-code buffer is empty until the line completes on a later pass at the same response_line progress - validates the keyword behaviour at this HTTP
progress value on both sides: a provisional (late) no match must not be turned
into a definitive no match (CANT_MATCH) while the buffer can still receive
data, while a definitive no match must still drop the flow.

## Scenario

`accept:flow http1:<response_line $EXTERNAL_NET any -> $HOME_NET any (http.stat_code; content:"200"; sid:211;)`.

Pcap (generated by `generate-pcap.py`, see `input.pcap`) carries two flows:

* A (port 49159): status line completes into `200` (keyword matches); B (port 49160): status line completes into `503` (no match)

## Expected

exactly 1 `firewall default app policy` drop (flow B): flow A is accepted when the status line completes, flow B is dropped (deferred to the eof CANT_MATCH, never waived).
