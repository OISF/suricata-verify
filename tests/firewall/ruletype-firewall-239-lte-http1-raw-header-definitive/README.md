# ruletype-firewall-239-lte-http1-raw-header-definitive

Regression test: a NON-streaming buffer behind an LTE hook, bounded at the
state where the buffer completes. `http.header.raw` is final at `request_headers`,
so the no match there is definitive and the LTE conversion must fire. A bound
above the buffer's state does not load at all: a firewall rule is only evaluated
at its hook, so the copy for a lower state would never run.

## Scenario

`accept:flow,alert http1:<request_headers $HOME_NET any -> $EXTERNAL_NET any (http.header.raw; content:"X-Marker: yes"; sid:211;)`.

Pcap (generated by `generate-pcap.py`, see `input.pcap`) carries two flows:

* A (port 49165): request headers contain `X-Marker: yes` (keyword matches); B (port 49166): request headers contain `X-Marker: no` (no match)

## Expected

exactly 1 `firewall default app policy` drop (flow B): the no match is definitive at the rule's own hook state (final buffer), so the LTE conversion fires at the first body pass - one state earlier than the streaming case (235).
