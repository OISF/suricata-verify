# ruletype-firewall-239-lte-http1-raw-header-definitive

Regression test: a NON-streaming contrast: `http.raw_header` is registered at HEADERS+1 (the request_body progress), where the raw header block is already final; the no match there is definitive and the LTE conversion must fire - validates the keyword behaviour at this HTTP
progress value on both sides: a provisional (late) no match must not be turned
into a definitive no match (CANT_MATCH) while the buffer can still receive
data, while a definitive no match must still drop the flow.

## Scenario

`accept:flow http1:<request_body $HOME_NET any -> $EXTERNAL_NET any (http.raw_header; content:"X-Marker: yes"; sid:211;)`.

Pcap (generated by `generate-pcap.py`, see `input.pcap`) carries two flows:

* A (port 49165): request headers contain `X-Marker: yes` (keyword matches); B (port 49166): request headers contain `X-Marker: no` (no match)

## Expected

exactly 1 `firewall default app policy` drop (flow B): the no match is definitive at the rule's own hook state (final buffer), so the LTE conversion fires at the first body pass - one state earlier than the streaming case (235).
