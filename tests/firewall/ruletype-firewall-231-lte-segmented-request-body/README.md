# ruletype-firewall-231-lte-segmented-request-body

Regression test: a provisional `http.request_body` no-match must not be turned
into a definitive no-match (CANT_MATCH) while the body can still grow at the
rule's own hook state.

## Scenario

`accept:flow http1:<request_body ... (http.request_body; content:"second";)`.

The pcap (generated by `generate-pcap.py`, see `input.pcap`) is an HTTP POST
with `Content-Length: 34` whose body arrives in two TCP segments:

* segment 1: `AAAAAAAAAAAAAAAAAAAA` (20 bytes, no keyword)
* segment 2: `secondBBBBBBBB` (keyword present)

On the first body segment the body engine has no matching content yet, but the
body is incomplete (20 of 34 bytes received), so the no match is provisional.
When the second segment arrives the keyword matches and the `accept:flow` rule
accepts the flow.

## Expected

* 0 `firewall default app policy` drops.

If the provisional no-match at `request_body` is treated as definitive
(CANT_MATCH), the flow is dropped by the default app policy on the first body
segment, before the matching second segment can be seen.
