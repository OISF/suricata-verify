# ruletype-firewall-233-lte-http1-request-line-split

Regression test: request line split over two TCP segments; the `http.uri` buffer is empty until the line completes (no partial line inspection), which can happen on a later pass at the same request_line progress - validates the keyword behaviour at this HTTP
progress value on both sides: a provisional (late) no match must not be turned
into a definitive no match (CANT_MATCH) while the buffer can still receive
data, while a definitive no match must still drop the flow.

## Scenario

`accept:flow http1:<request_line $HOME_NET any -> $EXTERNAL_NET any (http.uri; content:"/index"; sid:211;)`.

Pcap (generated by `generate-pcap.py`, see `input.pcap`) carries two flows:

* A (port 49153): line segments complete into uri `/index` (keyword matches); B (port 49154): line segments complete into uri `/admin` (no match)

## Expected

exactly 1 `firewall default app policy` drop (flow B): flow A is accepted when the line completes, flow B is dropped because the completed line never matches (the decision is deferred to the eof CANT_MATCH, never waived).
