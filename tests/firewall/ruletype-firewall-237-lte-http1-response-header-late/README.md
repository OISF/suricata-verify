# ruletype-firewall-237-lte-http1-response-header-late

Regression test: the late-arriving response header; the progress reaches response_headers when the status line completes, so the header values populate during response_headers passes - validates the keyword behaviour at this HTTP
progress value on both sides: a provisional (late) no match must not be turned
into a definitive no match (CANT_MATCH) while the buffer can still receive
data, while a definitive no match must still drop the flow.

## Scenario

`accept:flow http1:<response_headers $EXTERNAL_NET any -> $HOME_NET any (http.header; content:"X-Late: yes"; sid:211;)`.

Pcap (generated by `generate-pcap.py`, see `input.pcap`) carries two flows:

* A (port 49161): late header `X-Late: yes` (keyword matches); B (port 49162): late header `X-Late: no` (no match)

## Expected

exactly 1 `firewall default app policy` drop (flow B): flow A is accepted when the late header arrives, flow B is dropped (deferred to the eof CANT_MATCH, never waived).
