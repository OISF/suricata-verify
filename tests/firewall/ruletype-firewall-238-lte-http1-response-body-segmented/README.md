# ruletype-firewall-238-lte-http1-response-body-segmented

Regression test: the response body (file data) split over two TCP segments; it can still grow at the response_body progress - validates the keyword behaviour at this HTTP
progress value on both sides: a provisional (late) no match must not be turned
into a definitive no match (CANT_MATCH) while the buffer can still receive
data, while a definitive no match must still drop the flow.

## Scenario

`accept:flow http1:<response_body $EXTERNAL_NET any -> $HOME_NET any (http.response_body; content:"second"; sid:211;)`.

Pcap (generated by `generate-pcap.py`, see `input.pcap`) carries two flows:

* A (port 49163): second response body segment contains the keyword; B (port 49164): second response body segment does not

## Expected

exactly 1 `firewall default app policy` drop (flow B): flow A is accepted when the second response body segment matches, flow B is dropped when the completed body is definitively no-match (eof CANT_MATCH).
