# ruletype-firewall-234-lte-http1-request-header-late

Regression test: the late-arriving Host header; the progress reaches request_headers when the line completes, before any header line is parsed, so the header values populate line by line during request_headers passes - validates the keyword behaviour at this HTTP
progress value on both sides: a provisional (late) no match must not be turned
into a definitive no match (CANT_MATCH) while the buffer can still receive
data, while a definitive no match must still drop the flow.

## Scenario

`accept:flow http1:<request_headers $HOME_NET any -> $EXTERNAL_NET any (http.host; content:"latehost.example.com"; sid:211;)`.

Pcap (generated by `generate-pcap.py`, see `input.pcap`) carries two flows:

* A (port 49155): late Host header `latehost.example.com` (keyword matches); B (port 49156): late Host header `other.example.com` (no match)

## Expected

exactly 1 `firewall default app policy` drop (flow B): flow A is accepted when the late Host header arrives, flow B is dropped because the header never matches (deferred to the eof CANT_MATCH, never waived).
