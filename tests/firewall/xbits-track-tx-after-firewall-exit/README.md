# Description

In firewall mode, detection leaves a transaction early when a hook policy
accepts the packet. That exit must forget the transaction under inspection
like the normal end of the inspection does.

# PCAP

`input.pcap` is generated by `writepcap.py` (scapy) from the HTTP flow of
`ruletype-firewall-22-http-accept-tx-with-td`:

    python3 writepcap.py ../ruletype-firewall-22-http-accept-tx-with-td/http-sticky-server-s8.pcap input.pcap

Three copies of that flow on the same 5-tuple, each two hours after the
previous one. The flow has timed out when the next copy's SYN arrives, so the
worker evicts and frees it while looking up that SYN, before the packet is
inspected: the previous flow is gone whatever the flow manager does.
`--runmode single` keeps everything on one thread, so the next flow runs on
the thread that inspected the previous one.

# Rules

`firewall.rules` is that of `ruletype-firewall-22-http-accept-tx-with-td`,
with the stock configuration: the flow is accepted through packet hooks and an
`accept:tx` rule, after which every response packet is accepted by the hook
policy, the exit under test. `td.rules` sets a transaction bit from an IP-only
rule (sid 200), which runs on the first packet of each direction before any
app-layer, and from a packet rule on every established packet (sid 201).

# Expected

The run completes and the three flows are inspected alike.
The two bit-setting rules alert on every packet they match, no packet is dropped.
The bits they set cannot be observed; what the test pins is that setting them
is harmless.
