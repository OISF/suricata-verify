# ruletype-firewall-245-lte-http2-request-body-segmented

Per-buffer validation of the `http_client_body` `app_stream` registration
for http2 (the `http.request_body` keyword on the `http2:stream:request_data`
substate). Complements test 235, which covers the same buffer for http1.

## Scenario

`accept:flow http2:stream:<request_data $HOME_NET any -> $EXTERNAL_NET any
(http.request_body; content:"HTTP2MARKERABCD1"; sid:211;)`

Pcap (generated by `generate-pcap.py`) carries two plaintext HTTP/2 flows,
each sending one request (stream 1) with an 8192-byte body delivered in two
4096-byte DATA frames:

* A (port 49230): the marker "HTTP2MARKERABCD1" is in the second DATA frame.
  The first DATA pass (progress at request_data) sees a 4096-byte body
  without the marker; its no-match is provisional (the buffer is streaming)
  and the rule matches when the second frame arrives - the flow is accepted.
* B (port 49231): the second DATA frame carries the same-length replacement
  "NOMATCHDISC12345"; the body never matches. The engine's own eof
  CANT_MATCH at END_STREAM (progress passes request_data) rejects the rule
  and the flow is dropped once - streaming defers the decision, it never
  waives the drop.

The pcap deliberately omits the SETTINGS frames: the connection-level
(global) tx is presented to detection before the stream tx exists, and the
global states have no covering rules here - the default app policy would
drop the flow before the request body is even parsed. The global tx is out
of scope for this test.

## Expected

exactly 1 `firewall default app policy` drop (flow B).
