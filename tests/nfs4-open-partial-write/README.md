# nfs4-open-partial-write

An NFSv4 `OPEN` op with a `CLAIM4_DELEGATE_CUR` claim leads an oversized
`WRITE`, and the RPC record declares a size larger than the data ever
arrives.

An `OPEN` op is not in the partial-scan skip table: its `open_claim4`
argument is a *union* whose layout depends on the `claim_type`
discriminator (e.g. `CLAIM4_DELEGATE_CUR` carries a `stateid4` whose
sequence number a non-union-aware parser would misread as a filename
length). Advancing past such an op without a wire-faithful, union-aware
parse would land the scanner mid-record and return `Incomplete`, which
buffers the whole record toward the (attacker-controlled) 31-bit RPC
marker (Redmine #8791).

Instead, the scanner applies bounded rejection: a non-last op whose
arguments cannot be reliably skipped makes the whole compound `Malformed`.
The record is rejected and skipped to its marker boundary, so the
attacker's claim can never drive buffering.

The record is fed over two 4 KiB packets with the server acked in between
so the first packet is scanned in isolation. The check asserts the
`malformed_data` event (safe rejection), and — by construction — the
parser never buffers toward the 17 MiB claim.
