# nfs4-partial-response-open-read

A fragmented NFSv4 `OPEN; GETFH; READ` reply where the read is within the
`max-read-size` limit.

A valid response compound can carry an `OPEN` op before a `READ` op. The
partial response scanner (which walks the compound to find an oversized
`READ` before the RPC record is buffered) must skip the `OPEN` op's
successful result — stateid + change_info + result_flags + the fattr4
bitmap + the file_delegation4 union — to reach the following `READ`.
Without that skip the `OPEN` op is "not reliably skippable" and the
compound is rejected as malformed, so the read data is never inspected.

The reply is split over two packets with the peer acked in between so the
first packet is scanned in isolation. The read is within the limit, so the
scan is `Incomplete` (the data is not all buffered yet), the record
completes, and the 8192-byte read is inspected.

The check asserts the `fileinfo` event for the 8192-byte read and that no
`malformed_data` anomaly is raised.

Generated by `gen_nfs_review_tests.py` (test J).
