A malformed NFSv3 record as the first record of its flow.

The WRITE arguments stop after the file handle, so the parser cannot read the
offset, count and data. Two flows:

- **A** - the malformed WRITE is the flow's first record, so no transaction
  exists yet when the parser fails;
- **B** - a valid LOOKUP first, then the malformed WRITE, so the anomaly must
  land on the record at fault rather than on the newest transaction.

Raising the event on the state (`set_event()`) reported nothing for A and
pinned B's anomaly on the LOOKUP. It is now raised through an event-only
transaction carrying the record's xid, so both flows report `malformed_data`
and no `nfs` record is invented for the event.

`input.pcap` is generated by `gen.py`; tshark decodes both calls as NFSv3 WRITE
calls and flags the arguments as malformed, which is the point.
