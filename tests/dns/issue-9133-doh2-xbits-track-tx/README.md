# DoH2 transaction bits on 8.0.x

Redmine #9133, backport #9134.

The 8.0.x detection model unwraps the inner DNS transaction for DNS engines,
whereas main uses `doh2:stream` hooks. This stable-only companion to
`doh2-xbits-track-tx` uses `dns:request_complete` and
`dns:response_complete`, which are supported by 8.0.x. The main test retains
its original rules and full assertions.

The set/isset pairs must work on both completed DoH transactions, bits that
were never set must not match, and each transaction must see only its own
bits. Positive same-transaction reads keep the isolation checks from passing
because no bit was ever stored. Plain HTTP/2 set/isset controls verify the
outer protocol's transaction storage as well. The response-side `isset`
control uses the explicit `http2:response_complete` hook: stable requires an
application hook for transaction-bit reads. HTTP/2 response completion is
progress 7, whereas status-code inspection is progress 5, and stable requires
an exact hook/buffer progress match. Its HTTP/2 parser exposes no named
intermediate progress hooks. The readback rule therefore checks the bit at
response completion, and its EVE filter requires status 200 on both alerts.
A separate status-content rule must also alert twice, retaining the buffer
inspection control without combining incompatible progress values.

## PCAP

Uses `../../doh2-xbits-track-tx/input.pcap`, generated by the accompanying
`writepcap.py` in that directory. The fixture contains two completed DoH
exchanges, an unfinished intervening DoH request, and a plain HTTP/2 flow.
The retained main fixture documents the exact stream layout and crash path.
