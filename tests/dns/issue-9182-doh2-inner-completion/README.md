# DoH2 inner DNS completion on 8.0.x

Redmine #9182.

A DNS inspection engine on a DoH2 flow receives the inner DNS transaction.
When an inspected DNS multi-buffer has no values, completion must be checked
using that inner transaction's type, not by treating it as an HTTP/2
transaction. The wrong progress callback reads beyond the DNS allocation;
an ASAN build is needed to diagnose that memory-safety regression reliably.

The request carries no DNS answers. The `dns.answer.name` rules therefore
exercise the empty multi-buffer completion path: `absent` must match, and
`isdataat:1` must not. Query and response-answer positive controls prove
that inner DNS inspection ran. This test targets the stable-only engine
protocol correction, so it is limited to 8.0.8 and later 8.x releases.

## PCAP

Uses `../issue-9117-doh2-split-data/input.pcap`, generated by `gen_pcap.py`
in that directory. Both directions send a DNS message in a DATA frame
without END_STREAM, then an empty DATA frame with END_STREAM.
