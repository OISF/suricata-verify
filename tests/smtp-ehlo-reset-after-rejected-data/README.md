# Description

A DATA command sent before any envelope is rejected by the server (503),
but it still marks the transaction as having entered the data phase. A
mid-session EHLO must reset that abandoned attempt exactly as if a RSET
had been issued (RFC 5321 4.1.4), so the complete message sent afterwards
is parsed in a fresh transaction. Without the reset, the stale DATA state
made the parser drop the next DATA command, and the delivered message
body was never parsed as an email.

Redmine ticket: https://redmine.openinfosecfoundation.org/issues/8715

# PCAP

The pcap is a live capture of a real Postfix server, generated by the
email sandbox scenario `ehlo-reset-after-rejected-data` in
`smtp-oddseq.py`.

The important sequence is:

```
---> helo client.example.com
<--- 250 mail.example.com
---> data
<--- 503 5.5.1 Error: need RCPT command

---> ehlo client.example.com
<--- 250-mail.example.com (multiline)

---> mail from:<bob@example.com>
<--- 250 2.1.0 Ok
---> rcpt to:<alice@example.com>
<--- 250 2.1.5 Ok
---> data
<--- 354 End data with <CR><LF>.<CR><LF>
---> (message body)
---> .
<--- 250 2.0.0 Ok: queued as <id>
---> QUIT
<--- 221 2.0.0 Bye
```

Postfix rejects the envelope-less DATA, clears the attempt at the EHLO
and delivers the message from bob. The test checks that Suricata mirrors
this: two transactions, the first holding only the abandoned DATA
attempt, the second holding bob's fully parsed message.
